2React Component Boundaries
Key rule: Every chart component is a pure presenter. No hook or fetch call lives inside a chart. This makes them reusable for the Phase 2 user-selected ticker without modification.
3Data Service Abstraction
// financeService.ts — the only import used by hooks and components
interface FinanceService {
  getQuote(ticker: string): Promise<Quote>;
  getHistory(ticker: string, window: TimeWindow): Promise<HistoryPoint[]>;
}

// Adapter selected via env flag — never leaks into components
const adapter = import.meta.env.VITE_USE_MOCK
  ? mockAdapter       // static fixtures — active in CI and offline
  : yahooFinanceAdapter; // yahoo-finance2, server-side or via /api proxy

export const financeService: FinanceService = adapter;
Yahoo Finance practical note: yahoo-finance2 works server-side. For browser builds, add a lightweight Express proxy at finance-app/server/proxy.ts that Vite forwards /api/finance/* to. Only the adapter's base URL changes — no component code changes required.

5State Management Strategy

Recommendation: Zustand — minimal boilerplate, no Provider wrapping, easy to test in isolation.

interface DashboardStore {
  tickers:      Ticker[];               // DEFAULT_TICKERS from constants
  activeWindow: TimeWindow;             // 'day' | '7d' | 'quarter'
  quotes:       Record<string, Quote>;
  histories:    Record<string, HistoryPoint[]>;
  loadingKeys:  Set<string>;
  errors:       Record<string, string>;

  setWindow(w: TimeWindow): void;
  fetchQuotes(): Promise<void>;
  fetchHistories(): Promise<void>;
  addTicker(t: string): void;   // Phase 2 entry point — already scoped
}
6Error Handling
1
Network / adapter tier
yahooFinanceAdapter.ts — catch + rethrow typed FinanceError with ticker and reason fields.
2
Hook / store tier
fetchQuotes, fetchHistories write to errors[ticker] in the store. Never throw to components.
3
UI tier
CompanyCard, ComparisonPanel read errors[ticker] from store and show an inline ErrorBanner if set. An ErrorBoundary wraps DashboardPage as a last-resort catch.
4
Phase 2 — input validation tier
UserTickerPanel validates the symbol client-side before any network call. Invalid symbols produce a user-facing message without touching the main error store.
7Test Strategy
LayerToolWhat to test
Data transforms Jest normalizeQuote, normalizeHistory — input / output contracts
Hooks RTL + Jest useQuote, useHistory with mock adapter injected
Components RTL SummaryCard, CompanyCard, ComparisonPanel render + error state
Store Jest setWindow, addTicker, error accumulation
Integration RTL renderWithProviders DashboardPage mounted with mock service — verifies chart and card presence
The VITE_USE_MOCK=true flag ensures no network calls in any test. The mock data set covers: normal quote, partial/missing fields, and a deliberate error response for error-state assertions.
